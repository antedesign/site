Interpretable Context Methodology turns a folder of plain-language files into the instructions an AI agent follows. This is the starter kit: the idea, five use cases, a prompt that builds your first workspace, an example folder to download and the tools around it.

Interpretable Context Methodology maakt van een map met bestanden in gewone taal de instructies die een AI-agent volgt. Dit is het starterspakket: het idee, vijf use cases, een prompt die je eerste werkruimte bouwt, een voorbeeldmap om te downloaden en de tools errond.

Most advice on working with AI agents starts with the tool. This page starts with the task. The pattern that holds up across tools is small: pick one task that repeats, write down in plain language what goes in, what comes out and where a person checks, and keep that in a folder an assistant can read.

De meeste adviezen over werken met AI-agents beginnen bij de tool. Deze pagina begint bij de taak. Het patroon dat over tools heen standhoudt is klein: kies één taak die zich herhaalt, schrijf in gewone taal op wat erin gaat, wat eruit komt en waar een persoon controleert, en bewaar dat in een map die een assistent kan lezen.

That pattern has a name, Interpretable Context Methodology, or ICM. This page is the starter kit around it: the idea in plain terms, five worked use cases, a prompt that builds your first workspace with you, an example folder to download, and the tools that sit around all of it. It is a first version, and we will keep extending the tools, the prompts and the examples.

Dat patroon heeft een naam, Interpretable Context Methodology, kortweg ICM. Deze pagina is het starterspakket errond: het idee in gewone woorden, vijf uitgewerkte use cases, een prompt die samen met jou je eerste werkruimte bouwt, een voorbeeldmap om te downloaden en de tools die alles omringen. Het is een eerste versie, en we blijven de tools, de prompts en de voorbeelden uitbreiden.

What an agent is, in plain termsWat een agent is, in gewone woorden

Everyone says agent and few say what they mean. In this page an agent is an AI model that does more than answer. It reads files, uses tools, takes several steps and reports back. A chat answers a question. An agent works through a task.

Iedereen zegt agent en weinigen zeggen wat ze bedoelen. In deze pagina is een agent een AI-model dat meer doet dan antwoorden. Het leest bestanden, gebruikt tools, zet meerdere stappen en rapporteert terug. Een chat beantwoordt een vraag. Een agent werkt een taak af.

You meet agents in three forms: a chat where you attach files, an assistant built into an app you already use, and an agent that works inside a folder on your computer. This is our own way of sorting them, not a standard. The useful question is the same for all three: what does it read, and which rules does it follow while it works?

Je ontmoet agents in drie vormen: een chat waaraan je bestanden hangt, een assistent ingebouwd in een app die je al gebruikt en een agent die werkt in een map op je computer. Dit is onze eigen manier van sorteren, geen standaard. De bruikbare vraag is voor alle drie dezelfde: wat leest het, en welke regels volgt het terwijl het werkt?

Why folders, and why nowWaarom mappen, en waarom nu

Tools change faster than habits. Instructions that live in one product's memory stay behind when you switch from one assistant to another. Instructions that live as files in a folder travel with you.

Tools veranderen sneller dan gewoontes. Instructies die in het geheugen van één product zitten, blijven achter als je van assistent wisselt. Instructies die als bestanden in een map staan, reizen met je mee.

ICM answers three problems in particular:

ICM beantwoordt in het bijzonder drie problemen:

  • Tools that do not last. Whatever you set up in one product has to be rebuilt in the next.
  • Platform switches. Moving from one assistant to another should mean moving a folder.
  • No technical background. The structure is written in human language, so you can read it, correct it and explain it to someone else.
  • Tools die niet blijven. Wat je in één product opzet, moet je in het volgende heropbouwen.
  • Platformwissels. Overstappen van de ene assistent naar de andere zou een map verhuizen moeten betekenen.
  • Geen technische achtergrond. De structuur is in mensentaal geschreven, dus je kunt ze lezen, corrigeren en aan iemand anders uitleggen.

ICM from the inside outICM van binnen naar buiten

The core is three things: a folder structure, text a person can read, and routing. The folder structure says which task is next. The text says what to do in it. The routing says which files to load for it, and which to leave alone.

De kern bestaat uit drie dingen: een mappenstructuur, tekst die een mens kan lezen en routing. De mappenstructuur zegt welke taak aan de beurt is. De tekst zegt wat je erin doet. De routing zegt welke bestanden je ervoor laadt en welke je met rust laat.

From there it grows layer by layer. This page follows the reference repository, which counts five layers, numbered 0 to 4. The agent reads from the top down and stops as soon as it has enough.

Van daaruit groeit het laag per laag. Deze pagina volgt de referentierepository, die vijf lagen telt, genummerd van 0 tot 4. De agent leest van boven naar onder en stopt zodra hij genoeg heeft.

Five principles sit under the structure, taken from the repository's README:

Onder de structuur liggen vijf principes, overgenomen uit de README van de repository:

  1. One stage, one job. A stage that searches does not filter. A stage that stores does not process.
  2. Plain text as the interface. Stages hand each other files, not hidden state.
  3. Layered loading. Rules stay separate from the material you are working on.
  4. Every output is editable. The next stage reads what is there, including what you corrected.
  5. Configure the factory, not the product. What is stable gets written once, where every run can find it.
  1. Eén stage, één taak. Een stage die zoekt, filtert niet. Een stage die bewaart, verwerkt niet.
  2. Gewone tekst als koppeling. Stages geven elkaar bestanden door, geen verborgen toestand.
  3. Gelaagd laden. Regels blijven gescheiden van het materiaal waarmee je werkt.
  4. Elke output is bewerkbaar. De volgende stage leest wat er staat, ook wat jij gecorrigeerd hebt.
  5. Configureer de fabriek, niet het product. Wat stabiel is, schrijf je één keer op, waar elke run het kan vinden.

Six shapes, chosen by what repeatsZes vormen, gekozen naargelang wat zich herhaalt

A workspace does not have to be a production line. The companion repository, icm-architect, names six forms. Choose from what repeats in your work.

Een werkruimte hoeft geen productielijn te zijn. De begeleidende repository, icm-architect, noemt zes vormen. Kies vanuit wat zich in jouw werk herhaalt.

  • Pipeline: a production line: input goes through numbered stages
  • Umbrella: a portfolio of pipelines under one roof
  • Record library: people, clients or sessions, one record each
  • Knowledge bundle: a navigable knowledge base
  • Context map: an organisation represented as a graph
  • System map: a folder that later agents will edit
  • Pipeline: een productielijn: input gaat door genummerde stages
  • Paraplu: een portfolio van pipelines onder één dak
  • Dossierbibliotheek: personen, klanten of sessies, één dossier elk
  • Kennisbundel: een doorzoekbare kennisbank
  • Contextkaart: een organisatie voorgesteld als graaf
  • Systeemkaart: een map die latere agents zullen bewerken

One rule of thumb on where to keep the folder: a shared drive when you work with others, your own disk when it stays private. The method does not care, as long as the agent can read the files.

Eén vuistregel over waar je de map bewaart: een gedeelde drive als je met anderen werkt, je eigen schijf als het privé blijft. De methode maakt het niet uit, zolang de agent de bestanden kan lezen.

What ICM does not give youWat ICM je niet geeft

  • Proof. The source is a preprint by the method's authors. We found no independent evaluation. Treat it as a way of working to test, not a finding.
  • A fit for every job. The repository itself says it suits sequential, human-reviewed, repeatable workflows, and not real-time multi-agent collaboration, high-concurrency systems or complex automated branching.
  • Less checking. Interpretable here means you can see the workflow and its intermediate products. It does not mean you can see inside the model. A readable file does not explain why each word was chosen.
  • Full independence from tools. Folders travel. How an agent picks them up still differs per product.
  • Privacy by default. Files in a synced folder or in an AI tool are only as private as that tool's settings. Check them before you add sources about people.
  • Bewijs. De bron is een preprint van de auteurs van de methode. We vonden geen onafhankelijke evaluatie. Zie het als een werkwijze om te testen, niet als een bevinding.
  • Een match voor elke taak. De repository zelf zegt dat ze past bij sequentiële, door mensen nagekeken, herhaalbare werkstromen, en niet bij realtime samenwerking van meerdere agents, systemen met veel gelijktijdigheid of complexe automatische vertakkingen.
  • Minder controle. Interpretable betekent hier dat je de werkwijze en de tussenproducten kunt zien. Het betekent niet dat je in het model kunt kijken. Een leesbaar bestand verklaart niet waarom elk woord gekozen werd.
  • Volledige onafhankelijkheid van tools. Mappen reizen mee. Hoe een agent ze oppikt, verschilt nog steeds per product.
  • Privacy als standaard. Bestanden in een gesynchroniseerde map of in een AI-tool zijn zo privé als de instellingen van die tool. Check ze voor je bronnen over personen toevoegt.

Five use casesVijf use cases

Pick one. Each shows the folders, the sentence you say to start, and what a person still has to check. They are ordered from simplest to widest: start at the first even if your own situation looks like the last.

Kies er één. Elk toont de mappen, de zin waarmee je start en wat een persoon nog moet nakijken. Ze staan geordend van eenvoudigst naar breedst: begin bij de eerste, ook als je eigen situatie op de laatste lijkt.

Three habits that make it work betterDrie gewoontes die het beter laten werken

1. Speak instead of typing1. Spreek in plaats van te typen

Speaking is faster than typing and carries more context. For short prompts, the dictation built into your phone or computer is enough. For longer thoughts, interviews or a whole brain dump, use a tool built for that, such as Granola or a dictation tool like Wispr Flow. The tools section below groups more of them.

Spreken gaat sneller dan typen en bevat meer context. Voor korte prompts volstaat het dictee dat in je telefoon of computer zit. Voor langere gedachten, interviews of een volledige braindump gebruik je een tool die daarvoor gemaakt is, zoals Granola of een dicteertool zoals Wispr Flow. De sectie met tools hieronder groepeert er meer.

2. Let the AI ask you questions2. Laat de AI jou vragen stellen

Before a task, ask the AI to interview you, one question at a time, with a few labelled options to click or number instead of typing an answer. In our experience this gives better output every time, because the AI stops guessing what you meant. The prompt for it is in the closing section.

Vraag de AI vóór een taak om je te interviewen, één vraag per keer, met een paar genummerde opties om te klikken of te nummeren in plaats van een antwoord te typen. In onze ervaring levert dat telkens betere output op, omdat de AI stopt met raden wat je bedoelde. De prompt ervoor staat in de afsluitende sectie.

3. Know where you sit on the spectrum3. Weet waar je zit op het spectrum

AI use is not on or off. It runs from occasional to continuous. ICM is, for us, what moves work from using AI a lot to using it continuously: the system knows the task, so you stop re-explaining it.

AI-gebruik staat niet aan of uit. Het loopt van af en toe tot continu. ICM is voor ons wat werk verplaatst van veel AI gebruiken naar het continu gebruiken: het systeem kent de taak, dus je stopt met ze opnieuw uit te leggen.

Start with one task: four stepsBegin met één taak: vier stappen

  1. Pick one task that repeats and can be automated. Not the whole system. If you cannot name it in one sentence, it is too big.
  2. Build the context. Make one top file, CLAUDE.md in Claude Code or an equivalent in other tools, as the overview: what the agent does, which folder to look in, which step belongs where. You do not have to write it alone. Let the AI help, using the starter prompt below.
  3. Test and talk. Run it on a real input. Correct what is wrong by speaking, then ask the AI to write that correction into the instructions.
  4. Use it again. The more you run it, the more concrete and the better the workspace becomes. After every run, write down what you had to correct.

Common questionsVeelgestelde vragen

What does ICM stand for, and who made it?

ICM stands for Interpretable Context Methodology. It was published as a preprint by Jake Van Clief and David McDermott in March 2026, together with a reference implementation on GitHub under an MIT licence. The idea is to use numbered folders and plain-language files as the structure an AI agent reads and follows.

Waar staat ICM voor, en wie maakte het?

ICM staat voor Interpretable Context Methodology. Het werd in maart 2026 als preprint gepubliceerd door Jake Van Clief en David McDermott, samen met een referentie-implementatie op GitHub onder een MIT-licentie. Het idee is om genummerde mappen en bestanden in gewone taal te gebruiken als de structuur die een AI-agent leest en volgt.

Do I need technical knowledge to use it?

No code is involved. The files are plain text that you can read and change yourself, and the starter prompt on this page builds the first version with you through questions. What you do need is a clear idea of what goes in, what comes out and where a person checks the result.

Heb ik technische kennis nodig om het te gebruiken?

Er komt geen code bij kijken. De bestanden zijn gewone tekst die je zelf kunt lezen en aanpassen, en de startersprompt op deze pagina bouwt de eerste versie samen met jou via vragen. Wat je wel nodig hebt, is een duidelijk beeld van wat erin gaat, wat eruit komt en waar een persoon het resultaat controleert.

Does it only work with Claude?

No. The method is folders and text files, so it does not belong to one product. What differs per tool is how the files are picked up: some assistants read a folder and load the top instruction file on their own, in a chat-only assistant you upload or paste the files. Moving to another tool means moving the folder, not rebuilding it.

Werkt het enkel met Claude?

Nee. De methode bestaat uit mappen en tekstbestanden en hoort dus niet bij één product. Wat per tool verschilt, is hoe de bestanden worden opgepikt: sommige assistenten lezen een map en laden zelf het bovenste instructiebestand, in een assistent met enkel chat upload of plak je de bestanden. Overstappen op een andere tool betekent de map verhuizen, niet opnieuw bouwen.

Is ICM proven?

Not in the sense of independent, peer-reviewed evidence. The source is a preprint by the method's own authors, and the reference repository says it suits sequential, human-reviewed, repeatable workflows and fits poorly for real-time multi-agent collaboration, high-concurrency systems and complex automated branching. Treat it as a well-organised habit to test on your own tasks, not as a result.

Is ICM bewezen?

Niet in de zin van onafhankelijk, peer-reviewed bewijs. De bron is een preprint van de makers van de methode zelf, en de referentierepository zegt dat ze past bij sequentiële, door mensen nagekeken, herhaalbare werkstromen en slecht bij realtime samenwerking van meerdere agents, systemen met veel gelijktijdigheid en complexe automatische vertakkingen. Zie het als een goed georganiseerde gewoonte om op je eigen taken te testen, niet als een resultaat.

Should I start with one task or a whole system?

One task. Pick something that repeats, build the smallest workspace that does it, and correct it after every run. A whole system built in one go rests on guesses about tasks you have not run yet.

Moet ik starten met één taak of met een heel systeem?

Eén taak. Kies iets wat zich herhaalt, bouw de kleinste werkruimte die het doet en verbeter ze na elke run. Een heel systeem in één keer bouwen rust op gokken over taken die je nog niet hebt uitgevoerd.

The starter promptDe startersprompt

Let your own AI build the first workspace with youLaat je eigen AI samen met jou de eerste werkruimte bouwen

This prompt needs no knowledge of ICM. It asks whether you are setting up one task or a whole system, and advises one. It then interviews you, proposes the folders, writes the files one at a time and tests them. Paste it into ChatGPT, Claude or Gemini, or into an agent that can write files to a folder.

Deze prompt vereist geen kennis van ICM. Hij vraagt of je één taak of een heel systeem opzet en raadt één taak aan. Daarna interviewt hij je, stelt de mappen voor, schrijft de bestanden één voor één en test ze. Plak hem in ChatGPT, Claude of Gemini, of in een agent die bestanden naar een map kan schrijven.

You are an ICM workspace builder. ICM (Interpretable Context Methodology) organises AI work as numbered folders with plain-language instruction files, so that an AI assistant always knows where it is, what to do next and which files to read. I may know nothing about this method. Explain things in plain words, one step at a time, and never use a term you have not explained.

RULES FOR THIS CONVERSATION
- Ask before you build. Ask one question at a time. When the answer is a choice, offer 3 to 5 labelled options with your recommendation first, so I can answer with a letter or a number.
- Do not invent facts about my work. If you need something I have not told you, ask. Mark every assumption as [assumption].
- I make the decisions. You prepare, propose and check.
- Keep every file short and in plain language. Name folders in lowercase with hyphens.

STEP 1. SCOPE
Ask whether I want to set this up for ONE repeating task or for a whole system (a project, a thesis, a team). Recommend one task. Only continue with a whole system if I insist, and even then ask me to name the first task to build.

STEP 2. THE TASK
Interview me about the task: what goes in, what must come out, how often it repeats, which steps I take today, where I always check the result myself, which tools and files are involved, and what must never leave my machine or organisation. Summarise it back in six lines and ask me to correct it.

STEP 3. THE SHAPE
Propose a folder structure with numbered stages. One stage, one job. Show it as a tree and say in one sentence what each folder is for. Explain the five layers by pointing at my own files:
- Layer 0: a file named CLAUDE.md (other assistants use a similar name, such as AGENTS.md) at the top. It says where the assistant is and what the rules are.
- Layer 1: a CONTEXT.md that says where to go for which request.
- Layer 2: a CONTEXT.md inside each stage, with inputs, steps, outputs and what a human checks.
- Layer 3: material that stays the same between runs, such as rules, style guides and templates.
- Layer 4: material for this run, such as transcripts, drafts and outputs.
Ask me to approve or change the tree before you continue.

STEP 4. THE FILES
Write the content of every file in the tree, one file at a time, each in its own code block with its path as the heading. Every stage file must say: what to read, what to do, what to produce, and what a human must check before the next stage starts. Write instructions only, not outputs.

STEP 5. THE WALK TEST
Pretend you are a new assistant with no memory and only these files. Tell me where you would start, what you would read, what you would do on a first run, and what is missing or ambiguous. Fix the gaps with me.

STEP 6. FIRST RUN AND REPAIR
Tell me exactly where to put my first input and what to say to start. After each run, ask what I corrected and update the instructions so the same correction is not needed twice.

Begin with Step 1.
Je bent een ICM-werkruimtebouwer. Ik ken deze methode mogelijk niet. Leg dingen uit in gewone woorden, één stap per keer, en gebruik geen term die je niet eerst hebt uitgelegd.

STAP 1. AFBAKENING
Vraag of ik dit wil opzetten voor ÉÉN terugkerende taak of voor een heel systeem (een project, een thesis, een team). Raad één taak aan. Ga alleen verder met een heel systeem als ik erop sta, en vraag dan nog steeds welke taak we eerst bouwen.

STAP 2. DE TAAK
Interview me over de taak: wat erin gaat, wat eruit moet komen, hoe vaak ze terugkeert, welke stappen ik nu zet, waar ik het resultaat altijd zelf controleer, welke tools en bestanden erbij horen en wat nooit mijn toestel of organisatie mag verlaten. Vat het samen in zes regels en vraag me om te corrigeren.

STAP 3. DE VORM
Stel een mappenstructuur voor met genummerde stages. Eén stage, één taak. Toon ze als boomstructuur en zeg in één zin waarvoor elke map dient. Leg de vijf lagen uit aan de hand van mijn eigen bestanden:
- Laag 0: een bestand CLAUDE.md (andere assistenten gebruiken een gelijkaardige naam, zoals AGENTS.md) bovenaan. Het zegt waar de assistent is en welke regels gelden.
- Laag 1: een CONTEXT.md die zegt waar je heen gaat voor welke vraag.
- Laag 2: een CONTEXT.md in elke stage, met input, stappen, output en wat een mens nakijkt.
- Laag 3: materiaal dat gelijk blijft tussen runs, zoals regels, stijlgidsen en sjablonen.
- Laag 4: materiaal voor deze run, zoals transcripts, ontwerpen en output.
Vraag me de boom goed te keuren of aan te passen voor je verdergaat.

STAP 4. DE BESTANDEN
Schrijf de inhoud van elk bestand in de boom, één bestand per keer, elk in een eigen codeblok met het pad als titel. Elk stagebestand zegt: wat je leest, wat je doet, wat je maakt en wat een mens moet nakijken voor de volgende stage start. Schrijf enkel instructies, geen output.

STAP 5. DE WANDELTEST
Doe alsof je een nieuwe assistent bent zonder geheugen, met enkel deze bestanden. Zeg me waar je zou beginnen, wat je zou lezen, wat je zou doen bij een eerste run en wat ontbreekt of dubbelzinnig is. Los de gaten samen met mij op.

STAP 6. EERSTE RUN EN BIJSTUREN
Zeg me precies waar ik mijn eerste input moet plaatsen en wat ik moet zeggen om te starten. Vraag na elke run wat ik gecorrigeerd heb en pas de instructies aan zodat dezelfde correctie niet twee keer nodig is.
