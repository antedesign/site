Most advice on working with AI agents starts with the tool. This page starts with the task. The pattern that holds up across tools is small: pick one task that repeats, write down in plain language what goes in, what comes out and where a person checks, and keep that in a folder an assistant can read.

De meeste adviezen over werken met AI-agents beginnen bij de tool. Deze pagina begint bij de taak. Het patroon dat over tools heen standhoudt is klein: kies één taak die zich herhaalt, schrijf in gewone taal op wat erin gaat, wat eruit komt en waar een persoon controleert, en bewaar dat in een map die een assistent kan lezen.

That pattern has a name, Interpretable Context Methodology, or ICM. This page is the starter kit around it: the idea in plain terms, five worked use cases, a prompt that builds your first workspace with you, an example folder to download, and the tools that sit around all of it. It is a first version, and we will keep extending the tools, the prompts and the examples.

Dat patroon heeft een naam, Interpretable Context Methodology, kortweg ICM. Deze pagina is het starterspakket errond: het idee in gewone woorden, vijf uitgewerkte use cases, een prompt die samen met jou je eerste werkruimte bouwt, een voorbeeldmap om te downloaden en de tools die alles omringen. What an agent is, in plain termsWat een agent is, in gewone woorden

Everyone says agent and few say what they mean. In this page an agent is an AI model that does more than answer. It reads files, uses tools, takes several steps and reports back. A chat answers a question. An agent works through a task.

Iedereen zegt agent en weinigen zeggen wat ze bedoelen. In deze pagina is een agent een AI-model dat meer doet dan antwoorden. Het leest bestanden, gebruikt tools, zet meerdere stappen en rapporteert terug. Een chat beantwoordt een vraag. Een agent werkt een taak af.

You meet agents in three forms: a chat where you attach files, an assistant built into an app you already use, and an agent that works inside a folder on your computer. This is our own way of sorting them, not a standard. The useful question is the same for all three: what does it read, and which rules does it follow while it works?

Je ontmoet agents in drie vormen: een chat waaraan je bestanden hangt, een assistent ingebouwd in een app die je al gebruikt en een agent die werkt in een map op je computer. Dit is onze eigen manier van sorteren, geen standaard. De bruikbare vraag is voor alle drie dezelfde: wat leest het, en welke regels volgt het terwijl het werkt?

Why folders, and why nowWaarom mappen, en waarom nu

Tools change faster than habits. Instructions that live in one product's memory stay behind when you switch from one assistant to another. Instructions that live as files in a folder travel with you.

Tools veranderen sneller dan gewoontes. Instructies die in het geheugen van één product zitten, blijven achter als je van assistent wisselt. Instructies die als bestanden in een map staan, reizen met je mee.

ICM answers three problems in particular:

ICM beantwoordt in het bijzonder drie problemen:

Tools that do not last

Tools die niet blijven

Whatever you set up in one product has to be rebuilt in the next.

Wat je in één product opzet, moet je in het volgende heropbouwen.

Platform switches

Platformwissels

Moving from one assistant to another should mean moving a folder.

Overstappen van de ene assistent naar de andere zou een map verhuizen moeten betekenen.

No technical background

Geen technische achtergrond

The structure is written in human language, so you can read it, correct it and explain it to someone else.

De structuur is in mensentaal geschreven, dus je kunt ze lezen, corrigeren en aan iemand anders uitleggen.

ICM from the inside outICM van binnen naar buiten

The core is three things: a folder structure, text a person can read, and routing. The folder structure says which task is next. The text says what to do in it. The routing says which files to load for it, and which to leave alone.

De kern bestaat uit drie dingen: een mappenstructuur, tekst die een mens kan lezen en routing. De mappenstructuur zegt welke taak aan de beurt is. De tekst zegt wat je erin doet. De routing zegt welke bestanden je ervoor laadt en welke je met rust laat.

From there it grows layer by layer. This page follows the reference repository, which counts five layers, numbered 0 to 4. The agent reads from the top down and stops as soon as it has enough.

Van daaruit groeit het laag per laag. Deze pagina volgt de referentierepository, die vijf lagen telt, genummerd van 0 tot 4. De agent leest van boven naar onder en stopt zodra hij genoeg heeft.

Regels blijven gescheiden van het materiaal waarmee je werkt.

Wat stabiel is, schrijf je één keer op, waar elke run het kan vinden.

Six shapes, chosen by what repeatsZes vormen, gekozen naargelang wat zich herhaalt

A workspace does not have to be a production line. The companion repository, icm-architect, names six forms. Choose from what repeats in your work.

Een werkruimte hoeft geen productielijn te zijn. De begeleidende repository, icm-architect, noemt zes vormen. Kies vanuit wat zich in jouw werk herhaalt.

  • Pipeline: a production line: input goes through numbered stages
  • Umbrella: a portfolio of pipelines under one roof
  • Record library: people, clients or sessions, one record each
  • Knowledge bundle: a navigable knowledge base
  • Context map: an organisation represented as a graph
  • System map: a folder that later agents will edit
  • Pipeline: een productielijn: input gaat door genummerde stages
  • Paraplu: een portfolio van pipelines onder één dak
  • Dossierbibliotheek: personen, klanten of sessies, één dossier elk
  • Kennisbundel: een doorzoekbare kennisbank
  • Contextkaart: een organisatie voorgesteld als graaf
  • Systeemkaart: een map die latere agents zullen bewerken

One rule of thumb on where to keep the folder: a shared drive when you work with others, your own disk when it stays private. The method does not care, as long as the agent can read the files.

Eén vuistregel over waar je de map bewaart: een gedeelde drive als je met anderen werkt, je eigen schijf als het privé blijft. De methode maakt het niet uit, zolang de agent de bestanden kan lezen.

What ICM does not give youWat ICM je niet geeft

Proof

The source is a preprint by the method's authors. We found no independent evaluation. Treat it as a way of working to test, not a finding.

Bewijs

De bron is een preprint van de auteurs van de methode. We vonden geen onafhankelijke evaluatie. Zie het als een werkwijze om te testen, niet als een bevinding.

A fit for every job

The repository itself says it suits sequential, human-reviewed, repeatable workflows, and not real-time multi-agent collaboration, high-concurrency systems or complex automated branching.

Een match voor elke taak

De repository zelf zegt dat ze past bij sequentiële, door mensen nagekeken, herhaalbare werkstromen, en niet bij realtime samenwerking van meerdere agents, systemen met veel gelijktijdigheid of complexe automatische vertakkingen.

Less checking

Interpretable here means you can see the workflow and its intermediate products. It does not mean you can see inside the model. A readable file does not explain why each word was chosen.

Minder controle

Interpretable betekent hier dat je de werkwijze en de tussenproducten kunt zien. Het betekent niet dat je in het model kunt kijken. Een leesbaar bestand verklaart niet waarom elk woord gekozen werd.

Full independence from tools

Folders travel. How an agent picks them up still differs per product.

Volledige onafhankelijkheid van tools

Mappen reizen mee. Hoe een agent ze oppikt, verschilt nog steeds per product.

Privacy by default

Files in a synced folder or in an AI tool are only as private as that tool's settings. Check them before you add sources about people.

Privacy als standaard

Bestanden in een gesynchroniseerde map of in een AI-tool zijn zo privé als de instellingen van die tool. Check ze voor je bronnen over personen toevoegt.

What you still checkWat je nog zelf nakijkt
  • Check every quote against the transcript, and the transcript against the audio where it matters. Speech-to-text gets names, jargon and accents wrong.
  • Read the interviews one by one yourself. Let the AI do the clustering, not the reading.
  • Ask for consent before you record, and anonymise before you share.
  • Controleer elk citaat tegen het transcript, en het transcript tegen de audio waar het ertoe doet. Spraak-naar-tekst maakt fouten met namen, vakjargon en accenten.
  • Lees de interviews zelf één voor één. Laat de AI het groeperen doen, niet het lezen.
  • Vraag toestemming voor je opneemt en anonimiseer voor je deelt.

Common questionsVeelgestelde vragen

What does ICM stand for, and who made it?

ICM stands for Interpretable Context Methodology. It was published as a preprint by Jake Van Clief and David McDermott in March 2026, together with a reference implementation on GitHub under an MIT licence. The idea is to use numbered folders and plain-language files as the structure an AI agent reads and follows.

Waar staat ICM voor, en wie maakte het?

ICM staat voor Interpretable Context Methodology. Het werd in maart 2026 als preprint gepubliceerd door Jake Van Clief en David McDermott, samen met een referentie-implementatie op GitHub onder een MIT-licentie. Het idee is om genummerde mappen en bestanden in gewone taal te gebruiken als de structuur die een AI-agent leest en volgt.

Do I need technical knowledge to use it?

No code is involved. The files are plain text that you can read and change yourself, and the starter prompt on this page builds the first version with you through questions. What you do need is a clear idea of what goes in, what comes out and where a person checks the result.

Heb ik technische kennis nodig om het te gebruiken?

Er komt geen code bij kijken. De bestanden zijn gewone tekst die je zelf kunt lezen en aanpassen, en de startersprompt op deze pagina bouwt de eerste versie samen met jou via vragen. Wat je wel nodig hebt, is een duidelijk beeld van wat erin gaat, wat eruit komt en waar een persoon het resultaat controleert.

Does it only work with Claude?

No. The method is folders and text files, so it does not belong to one product. What differs per tool is how the files are picked up: some assistants read a folder and load the top instruction file on their own, in a chat-only assistant you upload or paste the files. Moving to another tool means moving the folder, not rebuilding it.

Werkt het enkel met Claude?

Nee. De methode bestaat uit mappen en tekstbestanden en hoort dus niet bij één product. Wat per tool verschilt, is hoe de bestanden worden opgepikt: sommige assistenten lezen een map en laden zelf het bovenste instructiebestand, in een assistent met enkel chat upload of plak je de bestanden. Overstappen op een andere tool betekent de map verhuizen, niet opnieuw bouwen.

Is ICM proven?

Not in the sense of independent, peer-reviewed evidence. The source is a preprint by the method's own authors, and the reference repository says it suits sequential, human-reviewed, repeatable workflows and fits poorly for real-time multi-agent collaboration, high-concurrency systems and complex automated branching. Treat it as a well-organised habit to test on your own tasks, not as a result.

Is ICM bewezen?

Niet in de zin van onafhankelijk, peer-reviewed bewijs. De bron is een preprint van de makers van de methode zelf, en de referentierepository zegt dat ze past bij sequentiële, door mensen nagekeken, herhaalbare werkstromen en slecht bij realtime samenwerking van meerdere agents, systemen met veel gelijktijdigheid en complexe automatische vertakkingen. Zie het als een goed georganiseerde gewoonte om op je eigen taken te testen, niet als een resultaat.

Should I start with one task or a whole system?

One task. Pick something that repeats, build the smallest workspace that does it, and correct it after every run. A whole system built in one go rests on guesses about tasks you have not run yet.

Moet ik starten met één taak of met een heel systeem?

Eén taak. Kies iets wat zich herhaalt, bouw de kleinste werkruimte die het doet en verbeter ze na elke run. Een heel systeem in één keer bouwen rust op gokken over taken die je nog niet hebt uitgevoerd.
